2. **每个文件解决了什么问题：**
   - 原`loadContent`在读取成功时直接设`guideStep=0`，引导立即将背景设为inert，导致发现状态机／落卡／光效被暂停。现在读取只更新业务数据，由首页在本次实际读取成功后调度引导。
   - 自动开启需同时满足当前账户与Home路由有效、本次读取成功、当前批次已呈现、发现状态机idle、无落卡与未结束融合光、页面可见、没有其他弹层和冲突操作。每次读取开始重置成功标志，避免筛选入口清除错误文案时绕过失败门控；双帧期间若数据源改变则重新安排。最后一张光效仍为真实2000ms；等待其实际结束，不用估算总时长或增加人为等待。
   - 经nextTick与两次可取消rAF保证目标已布局并有绘制机会，检查四个目标实际宽高后，开启或恢复原四步引导。原文案、位置算法与组件不变；成功空态使用空态面板／头像／分享入口／TabBar目标，减少动态直接展示真实结果后接引导。
   - `guideOpen`与账户内`guideStep`分离，避免引导自身inert引起开关循环。完成／跳过复用现有preferences保存，成功后关闭；失败保持当前步并可重试。未开始、离页、后台和打开帮助不保存guideDone。
   - 离页取消待开启的绘制任务及原装饰；沿用现有presentation.finish将已读取批次完整缓存的规则。返回先还原整组和滚动，再在本次读取成功与布局稳定后恢复引导当前步，不重播已完成动画。尚未读取成功的批次返回重读，不让旧回调在其他页面开启引导。
   - 顶部“？”仍为独立四页图文帮助，等待首次引导阶段也可主动打开；关闭恢复背景呈现并继续等待，不改guideDone。实际引导显示时避让帮助。未修改刷新顺序、权限、筛选、数据及唯一Native Bridge。
   - 实施前重新查询蓝湖首页、默认进入、四步引导及四页使用帮助目录，ID与更新时间保存在`design-reference.json`。同名引导4保留两个独立ID；目录API未返回可核验版本号，不将更新时间当版本。本次沿用已冻结静态视觉，不导入当前默认新版本，不新增切图或更改字体布局。
