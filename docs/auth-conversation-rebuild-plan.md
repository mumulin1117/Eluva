## 1 当前生效的范围

启动与协议 → 欢迎对话 → 首次／回访选择。

新用户：邮箱 → 固定验证码验证 → 姓名 → 年龄／完整生日 → 设置密码 → 主题 → 性别 → 快速问答 → 简介建议 → 保留或修改简介 → 原子完成注册 → Home。

回访用户：邮箱 → 密码 → 登录 → Home。未注册的邮箱保留输入并提供进入注册的明确选择，不自动创建账号。注册中发现邮箱已存在时，在原会话提供“密码登录／换个邮箱”分支。

忘记密码：原登录对话 → 邮箱 → 固定验证码 → 新密码 → 登录对话。注册验证与重置验证使用独立用途，不互相授权。

上述“→”表示对话状态推进。头像、消息上下文及当前输入区保持连续；不把每张设计稿实现为独立标题表单页。旧路由可保留为兼容入口，映射到统一会话状态，不能删除核心服务来规避兼容。

本次选择取代旧九步 Basic Info、University、Major、Photos、About、Interests、Connection Goal、Icebreakers、Notifications 的注册顺序。学校、专业、照片至少两张、兴趣至少三项、选择三个破冰问题及通知授权不再是新注册必经门槛。已有账户中的这些资料继续保留；资料编辑不在本轮新增或删除无关功能。

持续保留的确认：邮箱＋密码、注册和登录分支分离、固定验证码 `567567`、密码至少八位且含数字、18+ 按完整生日计算、生日不公开、简介最多 300 字、完整注册才创建账户、失败回滚与重复提交幂等。协议同意与 EULA 状态、英法双语、六尺寸、TabBar 隐藏、语言仅在设置切换继续有效。

## 3 快速问答与设计疑点

蓝湖明确显示 `6/6 Quick Quiz (n/10)`、每题 5 秒、二选一胶囊及部分题的 Skip；最后一题为 16 类 MBTI 自选。姓名、年龄、密码、主题、性别、问答为六个主阶段；简介为问答后的确认与提交。部分旧稿进度文本错位，不能机械复制错误的阶段编号。

题位、设计 ID、原文与选项逐一保存在 [结构化契约](./auth-conversation-contract.json)。目前能核实 10 个题位、9 条不同问句：

- 1：内向或外向。
- 2、3：原稿都为“Do you share your deep thoughts with AI?”，计数分别 2/10 与 3/10，确认是两张同题画面；不能编造一条未提供的新题来掩盖缺稿。
- 4：容易失去兴趣或慢热；5：直觉或逻辑；6：独处或与朋友相处。
- 7：是否容易与新认识的人开启交流；8：刺激内容或平静温暖内容；9：旅行计划或随性安排。
- 10：已知 MBTI 自选，允许 Skip；不能根据其他题自动推断未选择的类型。

以下属于**可逆实施方案，尚非用户新增确认**：

- 第 2、3 题暂保留两个独立题位与原文，配置标明重复待核，后续可替换第 3 题而不改历史答案主键；不宣称已有十条不同题目。
- 5 秒为蓝湖已有视觉；建议到时记 `timeout`、不代选并进入下一题，回答／跳过／到时只提交一次。后台和离页暂停计时，恢复后不批量补跳。确切到时策略及整组跳过方式须在实施问答小段前核对。
- 完成时长用实际有效作答时间；不展示虚构超越百分比、排行榜或抄写示例成绩。
- 题目属于自我表达，简介按实际回答使用可复现短句建议，不调用未授权 AI。跳过和超时不作性格推断。原始问答默认只向本人显示；用户保留／编辑的简介才进入公开资料。
- 原稿有 `IFNJ`、`IFFJ`、`INFP` 等不一致示例；只保存用户选择的有效 MBTI 值，生成文本与该值一致，不能照抄 Lisa 等示例资料。
- 性别稿使用 Yep／Nope，无法直接作为性别值；建议沿用既有稳定性别 ID 并采用明确标签，保留“不愿透露”，视觉仍为蓝湖胶囊。
- 主题显示名与已有 purple／pink／orange／cyan ID 关联；实际渐变和色值须按对应主题图层复核，不能只依英文名字猜色。

## 4 交互与保存边界

- 同一会话主滚动区、当前底部操作区。新消息出现时仅在接近底部时跟随；用户回看历史时提供回到当前问题入口，不强制抢滚动。
- 每条引导与回答使用稳定事件 ID；进入／返回／重试不重复追加。修改已答字段时按依赖撤销后续授权或重建建议，不保留与当前资料矛盾的回答。
- 邮箱：真实 email 输入、关闭自动首字母与拼写；trim／规范化后校验。修改邮箱撤销旧邮箱验证码授权并保留其他可复用资料草稿。
- 验证码：一个真实输入承接六格视觉，数字键盘、粘贴和删除可用；重发固定值不变。无真实邮件服务，不声称已发送邮件，也不恢复 Demo 标签。
- 年龄：保留对话提问位置，用完整生日面板落实已确认的 18+；出生年代不能替代完整年龄校验。不另加一次重复的年龄表单页。
- 密码：真实安全输入与显隐，只在气泡显示掩码／“密码已设置”；不得将密码写入消息、日志或问答配置。蓝湖单次设置密码不额外扩成新的重复确认必经页面；重置密码仍复用有效校验。
- 主题与问答只存注册内存草稿；取消后恢复先前视觉，不能提前写入另一账户偏好。成功提交时与新账户、简介、问答及主题偏好一起原子保存。
- 生成简介即时提供可保留／可修改的建议，不加入无意义强制等待；改稿只更新草稿。确认完成后才创建账户／会话，失败保留全部输入并重试，同一 commit 不重复建号。
- EULA 与社区同意分开记录，查看正文不等于同意。社区说明在对话内卡片承载是补齐方案，不重新铺独立标题页面；正式创建前必须满足现有同意约束。
- 从协议正文返回保留当前进程输入与滚动。2026-10-24用户确认移除Guide顶部返回及底部Start over，历史非敏感答案通过定点修改恢复原进度；取消修改保留原资料及验证状态，关闭进程不产生半成品账号。所有认证状态隐藏TabBar并释放底部占位。

## 5 必要代码与数据依赖（已落实，见实施报告）

`WelcomeView`、`AuthView`、`OnboardingView` 与认证专用对话容器负责连续呈现。复用真实输入、验证码输入、生日面板、按钮、弹层及现有视觉资源；认证会话不要写入好友聊天域。

`router.js`、`state.js` 需要从旧九步守卫改为对话状态守卫。对话状态与最终账户资料分离，编辑／返回和恢复不会绕过邮箱验证或最终提交。

`BrowserRepository` 与 `LocalRepository` 的 `beginRegistration` 当前先要求密码。需要兼容旧调用的小范围调整：新会话先按邮箱创建内存 flow，验证后再通过同一 Bridge 设置草稿密码，最终提交前重新检查密码有效性。缺密码、未验证、同邮箱冲突与重复回调均不得形成正式账户。

`validateProfile` 的 Web／Swift 实现当前对新账号强制照片≥2、兴趣≥3和破冰题=3。新流程必须有明确版本标识与新校验；旧账号原字段保留，不能用虚假占位照片／默认兴趣绕过规则。P5 `saveProfile` 当前采用字段白名单覆盖，必须确保新问答／流程版本不会在编辑资料后丢失；可将私有问答置于账户独立 `onboarding` 字段并保持与公开资料的边界。具体字段名仍为方案。

旧账号不重新做问答、不重建 ID、不清库、不重置关系与密码。新账号照片／兴趣等可为空，个人中心、主页和编辑页需通过已有占位和容错正常工作。必要的权威资料读取／编辑兼容属于直接依赖，不扩展其他模块。

## 6 实施顺序与出口

1. 锁定 ID／有效版本、补齐当前小段图层参数与素材；清楚区分原稿、邮箱替换和缺稿。
2. 完成开场、首次／回访、邮箱、验证码及已有账号密码登录的可操作小段；已有测试账号可登录，新用户可验证但未落正式账户，覆盖已注册、错码和失败重试。
3. 完成姓名、生日、设置密码、主题与性别，接注册 flow 和六阶段进度，处理上一步修改与取消。
4. 完成快速问答、跳过／到时、简介保留／修改及原子提交；先核对第 3 题与计时策略，不静默补题。
5. 完成忘记密码的同体系对话、旧账户兼容及新资料编辑往返；执行双语六尺寸、键盘、返回与异常、截图修正。
6. Web／原生测试、Vite、同步、资源审计、Xcode 构建及 WKWebView／真机分层验证；未执行项如实列出。每个小段均按“确认设计 → 提取资源 → 实现状态 → 接业务 → 返回异常 → 双语大小屏 → 构建”推进，不先铺全套静态页面。

本轮只更新规划与证据，未修改 `src`、`ios`、测试、资源或运行中的账户。没有新增页面截图、执行应用测试或构建；不会把设计图读取当作 iOS／真机验证。
