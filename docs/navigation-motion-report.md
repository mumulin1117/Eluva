2. **每个文件解决了什么问题：**
   - 二级页进入采用360ms轻推，返回320ms反向回退；Tab按Chats→Home→Mine的实际顺序做240ms短距离横移；发布页360ms上抬、返回320ms落下；媒体和通话页面采用200ms淡入。使用平缓减速曲线，位移限制在10–48px，不添加闪光或改变页面静态布局。
   - 保留单个live RouterView和原组件复用方式，不加fullPath key或KeepAlive，不保留旧页面组件。WebKit只对旧／新页面的合成快照做动画，离页清理照常发生；同一认证对话内部路由不整页转场。
   - 返回按钮大量使用router.push、Tab使用replace，因此方向依据有界的成功页面记录、显式from来源及父页面，而非仅比较URL深度或浏览器后退。取消和失败不更新记录，返回后的新分支不会复用已离开的旧分支。
   - 页面快照和TabBar快照分开，toast与body中的弹层不纳入页面快照；混合模式normal避免半透明页面在默认叠加中发亮。关闭操作弹层及安全状态更新先完成DOM提交；仍有弹层或已不可访问的来源跳过捕获。
   - 初始启动继续使用既有LaunchScreen→H5首帧交接，确认首帧之前不添加页面转场。切换账户取消并清空内存中的视觉方向记录，避免保留前一账户快照。
   - 连续导航取消旧转场；等待DOM期间以代际号抛弃过期任务。取消、路由错误、捕获失败、后台、视口／键盘高度变化、减少动态效果和销毁均释放快照、动画、RAF、计时器及等待。200ms捕获兜底和1200ms总兜底避免路由停在冻结画面；这些是异常恢复上限，不是业务加载等待。
   - 不支持快照API时，使用原页面容器的短距离Web Animation；通话页始终用淡入回退，避免捕获相机／视频表面。系统减少动态效果开启后直接切换。转场不占用业务busy、不设置#app inert、不更改请求和骨架节奏。
