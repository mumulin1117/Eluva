# 同频详情与联系规则纠偏（2026-10-20）

## 已确认

- 详情不提供评论；旧评论数据兼容保留。
- 多图每 2 秒轮播，手势、分页点与底部 current/total 同步。2026-10-20 用户进一步确认：单图底部显示居中的 `1/1`，不显示多图分页点；无媒体时不显示页码。后台、离页、弹层、触摸、减少动态效果时暂停。
- 点亮仅揭示作者卡，不产生关注或聊天权限。
- 双方互相关注，或动态 Reply 的接收者实际回复后，才允许持续聊天。
- 每对用户最多一条待回复的动态 Reply，跨动态共享；发送后按钮灰色，点击解释等待原因。接收者可 Decline，或发送回复并原子建立联系。
- 已互关或已经建立联系时，Reply 进入正常会话。

## 数据和兼容

- 在现有 social v1 中增加 connections 字典；按稳定 pair ID 存储 pending/connected/declined 及来源动态、消息 ID。使用现有 social Bridge 服务新增方法，不另建通信层。
- 初始 Reply 必须有可见动态和当前点亮权限，保存初始消息、连接状态、会话及去重记录为一次原子事务；失败不占用机会。
- 回复提交时同时保存消息和 connected 状态；Decline 幂等，失败保持 pending。已拒绝关系不自动解锁，不重新开放同一对用户的陌生联系，避免重复打扰；可通过双方互关解锁。
- 既有已接受好友关系一次性补入双方关注，以保留既有可聊天关系；之后取消任一关注即撤销此路径的权限，已通过 Reply 建立的联系仍有效。历史 friendships 不删除、不单独作为第三种聊天授权。
- 旧好友申请接受后建立互关；关注、点亮、Reply 状态仍各自独立。
- 删除账户时仅清理涉及该账户的 connection 元数据；保留既定其他账户消息处理规则。

## 入口、返回和保存

- 详情返回沿用 from；个人主页返回保持详情索引。打开大图、弹层和页面返回保留索引及合理滚动。
- Reply 草稿按账户和 peer 保存在既有 social 内存状态；取消、返回、换语言均保留。成功才清空，busy 防重发；灰色按钮不使用原生 disabled，从而可解释等待原因。
- 消息页可读取待回复会话；发送者仅可查看，接收者只可发送一次文字回复解锁，解锁后正常媒体控件可用。拉黑优先于所有授权。
- 2026-10-22：他人动态右上角 More 直接复用他人主页 SocialSafety 的图标式底部菜单、取消与拉黑确认。动态举报进入同款独立举报页，携带稳定 postId；主页举报继续携带 peerId，草稿按账户／目标类型／目标 ID 隔离。拉黑成功沿安全来源链退出相关详情及主页，隐藏相关内容、会话和请求，不删除历史。自己的动态保留删除／隐藏。验证见 [More 统一报告](./post-more-implementation-report.md)。
